Install Disk Forecast, a free macOS menu bar app (https://github.com/coreyhaines31/diskforecast), on this Mac:

1. Check that macOS is 14 or later with `sw_vers -productVersion`. If it's older, stop and tell me.
2. If Homebrew is installed (`command -v brew`), run:
   brew install --cask coreyhaines31/tap/diskforecast
   Otherwise, install the latest release from GitHub:
   url=$(curl -fsSL https://api.github.com/repos/coreyhaines31/diskforecast/releases/latest | grep -o 'https://[^"]*\.dmg' | head -1)
   curl -fsSL -o /tmp/DiskForecast.dmg "$url"
   mnt=$(mktemp -d) && hdiutil attach -nobrowse -quiet /tmp/DiskForecast.dmg -mountpoint "$mnt"
   cp -R "$mnt/Disk Forecast.app" /Applications/ && hdiutil detach -quiet "$mnt" && rm /tmp/DiskForecast.dmg
3. Check it's notarized: `spctl --assess --type exec -v "/Applications/Disk Forecast.app"` should say "Notarized Developer ID".
4. Open it: `open -a "Disk Forecast"`.
5. Open the Full Disk Access settings for me:
   open "x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles"
   Then tell me to turn on Disk Forecast there (it's optional), that its tape reel icon with my free space is now in the menu bar, and that from now on I can ask you why my disk is filling up or what's safe to clear. You'll use the `diskforecast` command (see `diskforecast --help`; if it isn't on the PATH, it's at "/Applications/Disk Forecast.app/Contents/MacOS/diskforecast").

6. Ask me whether future agent sessions should know about it. Only if I say yes, append this to your own global instructions file (~/.claude/CLAUDE.md for Claude Code, ~/.codex/AGENTS.md for Codex), unless it's already there, and tell me which file you changed:

   ## Disk space
   Disk Forecast is installed. For disk questions, or on "No space left on device", run `diskforecast status`, then `diskforecast cleanup` (see `diskforecast --help`; if it isn't on the PATH, it's at "/Applications/Disk Forecast.app/Contents/MacOS/diskforecast"). Only move things to the Trash when I say so.

Apart from that, don't change any other settings and don't delete anything.

Why is my Mac storage full?

It's usually three questions at once, and Storage settings leaves all three open.

“Where did 40 GB go?”

Storage settings shows what's on the disk today, not what changed. Disk Forecast saves folder sizes after every scan, so it can name the folder that grew and say since when.

“Why is System Data so big?”

Apple's own help says you can't manage what's in it. Disk Forecast names the parts, like local Time Machine snapshots, simulator runtimes, the Spotlight index, and Docker, and fixes each with its owner's own tool.

“What can I delete safely?”

Every item on the cleanup list says what it is and what happens when it goes. Things that rebuild themselves come checked. Everything else waits for you, and it all goes to the Trash first.

The Forecast window compares today with the start of the range you pick and lists every folder that changed by more than 500 MB, biggest first. Open one to see which of its folders did it. New folders are marked New. Space that changed outside your home folder, like System Data, other accounts, and apps, gets its own line.

What's taking up space on my Mac?

Open the menu and the five biggest folders are right there, named at a useful depth. When a folder is mostly one subfolder, the way ~/Library is mostly ~/Library/Developer on a developer's Mac, the menu shows the subfolder instead, up to four levels down. The list names what's actually big.

Each one opens a submenu with what Cleanup knows inside it, biggest first. Pick one and Cleanup opens at that item. Show in Finder takes you to the folder itself.

When Cleanup doesn't know a folder, it says so. Suggest a Rule opens a GitHub issue filled in with the folder's location and size, asking what makes it and whether it comes back. Nothing is sent until you submit it, and you can edit it first.

New in 1.10, the storage meter under the forecast splits used space into Apps, Developer, Photos, Movies, Documents, Music, Caches, Trash, and System and other, each counted once. Pick the Peak meter, rows of lit dots, or the VU meter, a tape for each category, in Settings › General. Hover a category to see its share. With Full Disk Access on, Empty Trash sits right below it.

Cleared where it's safe

  • WhatsApp mediaPast 5 GB, with the biggest chats named. A known sync bug can fill it past what WhatsApp shows. Opens WhatsApp.
  • Messages attachmentsPast 2 GB, with the biggest conversations. Trashing them by hand would leave broken attachments. Opens Messages.
  • Signal attachmentsEncrypted and only on your devices, so they can't be downloaded again. Opens Signal.
  • Telegram and Telegram Desktop mediaStill in Telegram's cloud. Its own storage settings clear it by chat.
  • Docker disk imageOne file holding everything Docker stores. Reclaimed with Docker's own prune in System Data, not by deleting the file.

WhatsApp, Messages, and Telegram keep their media in folders macOS guards, so they show up once Full Disk Access is on. Missing a folder you know about? Use Suggest a Rule from the menu.

Nothing goes without asking.

Move to Trash… opens one dialog with the total, what's in each category, and anything that has to stay. Open files stay put, because the app or Claude Code session using them would keep using the trashed copy.

  • Trash by default. Delete Immediately is there when you need the space now, and it says it can't be undone.
  • Undo. It puts back everything the last run moved, from the app or with diskforecast undo, until you quit.
  • Quit and Try Again… It names each app and Claude Code session first. Apps quit the usual way, so one with unsaved work asks, and Claude Code conversations pick up again with claude --resume.
  • Disk too full for the Trash? Moving to the Trash needs a little free space. It tells you, and offers Delete Instead or Empty Trash.
  • Empty Trash… It deletes even what Finder can't, like folders whose paths are too long, after asking with the item count.
  • Home folder only. It moves things inside your home folder, plus Claude Code's own temp sessions. Never your home folder or its standard folders, and never through a link that leads out.

Careful by default.

Nothing is deleted without asking, nothing leaves your Mac, and nothing costs a thing.

Trash first

What you clear goes to the Trash, where you can put it back. Delete Immediately and Empty Trash are there when you need the space now, and both ask first.

Apple's own tools

System fixes run tmutil, mdutil, or xcrun simctl, and show you the command first.

Counted once

APFS clones and hard links share space on disk, so they're counted once and totals aren't inflated.

Home folder is enough

Full Disk Access is optional. Cloud drives like Dropbox are never scanned.

Stays on your Mac

No telemetry, no account. The only network call checks for updates, and you can turn it off.

Free. Really.

No trial, no subscription. Source on GitHub, signed and notarized by Apple.

What it reads

  • Names and sizes of the files in your home folder. To name your biggest chats, it reads WhatsApp's and Messages' own databases on your Mac, read-only.
  • Free space on the startup disk, once an hour.
  • With Full Disk Access, the folders macOS guards: Mail, Messages, Safari, iCloud Drive, and other apps' containers.
  • Its own history in ~/Library/Application Support/Disk Forecast: a reading a day and folder sizes, 120 days of each.

What it never does

  • Scan cloud drives in ~/Library/CloudStorage, like Google Drive, Dropbox, and OneDrive.
  • Download iCloud files that macOS offloaded to make room.
  • Ask for Photos, Music, or TV access. Without Full Disk Access, those libraries are skipped.
  • Send anything about your disk anywhere. There's no analytics in the app.

What it asks for

  • Full Disk AccessOptional. Without it, macOS asks once each for Desktop, Documents, and Downloads.
  • NotificationsThe first time it has something to warn you about.
  • Your passwordOnly to rebuild the Spotlight index, and macOS asks, not the app.
  • Launch at loginOn from the first launch, so readings continue after a restart. Off in Settings.

Questions

Is it safe?

Yes. Cleanup moves files to the Trash, where you can put them back, unless you choose Delete Immediately. Empty Trash deletes what's already in the Trash, even items Finder can't, like folders whose path is too long, and both ask first. Safe to clear only holds things that rebuild themselves, like caches and build folders. Anything an app or a Claude Code session still has open is left alone, and Disk Forecast says which one. It can quit them for you and try again, after naming each one. System Data fixes, like removing local Time Machine snapshots, run Apple's own tools after you confirm.

Will it warn me before my disk is full?

Yes. When the forecast says your disk will be full within a week, or space runs low, you get a notification naming what grew most that week and how much emptying the Trash would get back. At most once a day, and you can turn it off in Settings.

How accurate is the forecast?

It's a trend, not a promise, which is why it says “~”. It follows the typical day-to-day change in free space over the last two weeks, so one big download or cleanup doesn't throw it off. It appears after 3 days of history and says how fast space is changing: “Full in ~41 days · using 3.5 GB a day”, “Steady”, or “Free space growing”. When space is low, it says so whatever the trend.

Why does it want Full Disk Access?

It doesn't need it. Everything works with your home folder. Full Disk Access lets it measure the folders macOS guards, like Mail, Messages, iCloud Drive, and other apps' containers. Without it, their space shows up as unexplained.

What is System Data?

The catch-all bar in Storage settings for everything macOS doesn't file under a named category: local Time Machine snapshots, purgeable space, simulator runtimes, caches, Apple Intelligence models, the Spotlight index. The guide walks through each one.

Does it slow down my Mac or drain the battery?

It's built not to. Between scans it reads free space once an hour, a single question to macOS. Scans run about twice a day at background priority, on the efficiency cores with throttled disk reads, and one that falls due on battery waits for the charger unless the last scan is more than a day and a half old. Choose Rescan in the menu whenever you want a fresh count at full speed.

Which Macs does it run on, and how do I install it?

Any Mac on macOS 14 Sonoma or later, Apple silicon or Intel. Download the DMG from GitHub and drag Disk Forecast to Applications, or run brew install --cask coreyhaines31/tap/diskforecast, which also puts the diskforecast command on your PATH. It has no Dock icon: look for the tape reel in the menu bar.

Why not the App Store?

App Store apps run in a sandbox that can't see most of your disk, so a disk tool there can't measure System Data or run Apple's fixes. Disk Forecast is signed and notarized by Apple, and installs from GitHub or Homebrew.

How do I update or uninstall it?

It checks for updates on its own, and Check for Updates… in the menu checks now. With Homebrew, brew upgrade --cask diskforecast works too. To uninstall, run brew uninstall --cask --zap diskforecast, or move Disk Forecast from Applications to the Trash and remove ~/Library/Application Support/Disk Forecast, where its history lives.

Can my AI agent use it?

Yes. Disk Forecast comes with a diskforecast command, so Claude Code, Codex, or any agent that runs commands can check the forecast, see which folders grew, and list what's safe to clear. It can only move things on the cleanup list, only to the Trash, and shows what it would move until it's told --yes. Homebrew puts the command on your PATH. Every command.

Does it clean up after coding agents?

Yes. It finds the git worktrees Claude Code, Codex, and other agents leave behind and lists each under Worth a look with what removing it would lose: changed files and commits no remote has. Removing one also clears git's records of it, like git worktree remove. Under Safe to clear, it lists what agents download to work: npx packages like MCP servers, older browsers for Playwright and agent-browser, older Claude Code versions, and the temp files Claude Code leaves in /private/tmp after a session, which can reach tens of gigabytes. More on git worktrees.

Is it really free?

Yes, at home or at work. No account, no trial, no subscription. The source is on GitHub, so you can read exactly how it counts and what it moves to the Trash.

Why it exists

I build a lot of side projects, and my Mac kept filling up without warning. Storage settings lumped most of it into System Data and stopped there, and the tools that explain it cost $10 to $49.
